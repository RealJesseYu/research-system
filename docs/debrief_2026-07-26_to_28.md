# Debrief — the session that made the system stop being weaker than a chat

**Span:** 2026-07-24 evening → 2026-07-28 afternoon.
**Scale:** 42 commits from this session (71 total on the branch across all
sessions), 155 files, +19,816 / −659 lines. Suite **1,514 → 2,084** passing.
**Live evidence:** 30 studies on disk; four of them substantive.

This is the honest record, including the parts where I was wrong, because the
wrong turns are the reusable part.

---

## 0. How the session started, and what it turned into

It opened as a documentation request — *"summarize the capabilities of the
current system"* — and became an audit, then a rebuild, because answering the
question honestly required reading the code rather than the docs, and the code
did not do what the docs claimed.

The turning point was the owner pasting his own prompt into a plain Claude chat
and getting back a markedly better piece of research than his system produced.
Everything after that was chasing the gap between those two artifacts.

---

## 1. The central finding: the system was caged in seven places

Not one bug. A **pattern**: a prompt forbidding what the agent could already do,
or a gate enforcing a constraint that had stopped being true. Each was invisible
in isolation and devastating in combination.

| # | The cage | What it did |
|---|---|---|
| 1 | `record_move` copied `raw["findings"]`; ideation returns `"hypotheses"` | **The director never saw a single idea it asked for.** A 15.9M-token full-depth ideation reached it as an empty receipt, and it confabulated a hypothesis to fill the gap |
| 2 | *"Judge NOVELTY strictly against those snippets"* | A reviewer holding WebSearch was forbidden to search. Retrieval returned 6 irrelevant refs, so "novel" was the ONLY verdict the validator would accept — for a claim whose prior art dates to 1974 |
| 3 | Validator rejected any citation outside the pre-fetch | The anti-hallucination fix enforced honesty by making the reviewer blind |
| 4 | `FEASIBILITY_NUDGE`: anything outside a solver's parameter list is *"worth nothing here, however novel or well-motivated"* | Confined every idea to the handful of questions standard solvers already answer — which is why **16 of 16 came back already-answered** |
| 5 | `routable_contracts_block()` in the generation context | Even after the veto was removed, the menu still **primed** every proposal. Permission changes do not undo priming |
| 6 | The director enumerated instruments in its own ideation request | The same anchor, one level up |
| 7 | Model pins were `claude-opus-4-8` / `claude-sonnet-4-6` | **The whole system ran a generation behind the chat it was being compared to**, and 119 of 140 ideation calls were on the light tier |

Every one is now fixed. The lesson generalizes: **when a system underperforms,
look for what it is forbidden to do before concluding it cannot.**

## 2. What shipped, by theme

### Work compounds across phases

- **The carry bus** (`b643585`) — verified file artifacts flowed *up* into the
  arc but reached exactly one consumer. Every other dispatch got only prose, so
  each move rebuilt the world from a sentence. Producers now flow *down* into
  `run_experiment` and `spawn`, and a spawned child is seeded so the hand-off
  survives recursion. **Live-proven:** a control-law phase inlined the wing
  phase's producer, regenerated `glider_design.json`, and built on it.
- **The experimenter is briefed** (`41d48eb`) — a run used to receive one line
  and no idea what investigation it belonged to. It now gets the goal, what is
  established (verified only), why this experiment now, and permission to
  deviate.
- **Ideation is briefed too** (`3798326`) — it had none of that, which made the
  apparatus useless for *"half the system is built, find the next step."*

### Nothing may end an arc but the director

- **`b717512`** — neither `run_move` nor `execute_capability` was guarded, so any
  exception below them killed the study and threw away everything already
  verified. Both live crashes took that path.
- **`3f1cdfa` / `017dbe6`** — a transport hiccup (`"Claude Code returned an error
  result: success"`) ended a healthy study with six moves unspent. The director's
  decision is now retried, then recorded, and only repeated failure terminates.
- **`da5b616`** — a screening stage raised on zero survivors. Twice, on two
  successive predicates. A screen reports; it does not veto.

### The deliverable stopped being a pile of numbers

- **Study-level papers** (`ec48a5d`) — a director-run study produced **no paper at
  all**; `free_paper` wrote up one run and the director never called it. Plus a
  dead `stage6/paper.md` lookup that made `paper_path` permanently `None`.
- **Citation check** (`5586ca2`) — the paper claimed *"independently reproduced"*
  for a number the wall had **rejected** (128.0 → 127.49). A prompt is not a
  guarantee; a deterministic post-check now appends a correction.
- **The work travels** (`f483537`) — `reusable_artifacts` was framed as optional,
  so an agent optimizing for credit produced analysis and treated the thing it
  built as scaffolding.
- **Form follows the goal** (`f483537`) — the write-up prompt hardcoded "write a
  scientific paper" for every possible goal. Ask for homework help, get a paper.
- **Provenance tags** (`ef726c2`) — VERIFIED / COMPUTED / JUDGEMENT on every
  specified value, because *"an airfoil choice and a reproduced eigenvalue read
  identically on the page, and only one has been checked."*

### Verification records, it does not gate

- **`38db358`** — `rel_tol=1e-6` is a bit-exactness test that rejected legitimate
  convergence-dependent results and killed ~60% of a good study's findings.
  Claims may now declare a tolerance, clamped so it can only loosen an
  obstructing check. And `publishable` stopped meaning "nothing failed."
- **`0dd3019`** — a SHA-256 that re-ran **character-for-character identical** was
  refused as `non_numeric`. Exact string equality is reproduction. Needed fixing
  in two places, since the sandbox coerced every metric through `float()`.

### Proportionality

- **`5d1c0fb`** — the glider study derived one glide ratio three independent
  ways, cross-checked Lyapunov against Monte Carlo, and swept 32 robustness
  corners. **Verified findings are the only thing the system scores**, so
  confirming an easy number was the cheapest way to look thorough. One good check
  per claim; breadth beats depth; escalate an easy question rather than
  exhausting it.
- **`8df1835` / `37c7d1f` / `c296689`** — ideation was **157 calls at a mean of
  127 seconds each, entirely serial**, with a triage gate that passed 21 of 25.
  Now: pool 76, top-6 deep-reviewed, three reviews merged into one `scrutiny`
  call, six concurrent. **~107 calls → ~35, for three times the hypotheses.**

### A third reviewing lens

- **`72ea67f`** — the owner pasted a finished study into a fresh chat and asked
  *"can I build this today?"* Six true findings the whole apparatus had missed —
  no structural check, no pitch axis, no cut files. **None was a correctness
  failure.** Things were *absent*, and absence is invisible to a verifier. The
  build critic asks the practitioner's question and routes findings **back to the
  director** for one recorded response.

## 3. What the live runs actually proved

**`study-20260726T010756Z` — test-time augmentation for a CAS.** A real
cross-domain transplant with a proper control arm (trivially re-encoded copies,
isolating augmentation from retry), pre-registered endpoint, exact McNemar,
CAS-free audit. Reported an honest null: p = 0.0625, ~2 points, 104 calls per
additional solve.

**`study-20260726T063702Z` — glider v1.** Integration found the composed vehicle
at **99.94% of its rudder limit**, with the unsaturated command at 126% — a
failure **invisible in either subsystem's verified numbers**. That is the entire
argument for `call_integration`, demonstrated.

**`study-20260726T185547Z` — glider v2.** A design document leading with the
aircraft, a planform drawing, 127 provenance-tagged values, and §4.1 titled *"The
headline glide ratio itself is partly unreproduced"* — demoting its own headline
because only one of three routes reproduced. Also the clearest failure: ~90%
verification, ~10% design, on a five-minute problem.

**`study-20260727T091129Z` — the smoke test.** Downloaded NASA GISTEMP
autonomously, verified the statistic, cross-checked file size against
`Content-Length`, and stopped at **6% of budget** saying *"spending the remainder
on more routes to the same number would be effort, not progress."* The
proportionality doctrine, working, in the system's own words.

## 4. Where I was wrong

**I graded the harness, not the research.** I reported "the science was better
than I expected" about a study whose central claim — adjoint methods for design
optimization — dates to Pironneau 1974 and Jameson 1988. The owner caught it. I
was checking that dials fired while he was checking whether the work was any
good.

**I proposed deleting the hypothesis apparatus.** Wrong. The owner corrected me:
its value is *volume* — 100 screened hypotheses is something a chat will never
do. I nearly removed the one component that is structurally not-a-chat.

**I mistook a search-space problem for a model problem.** Twice: first blaming
the generator, then the filter, when the cause was a constraint telling it that
anything off the solver menu was worthless.

**I said "agents can't generate or validate geometry."** Flatly wrong — the
experimenter runs FULL. The true statement was much narrower: nothing *asked* it
to.

**And the correction I did not make.** The coordinating session established that
`stages/verification.py` is deterministic Python with **no model in the path** —
so the wall spends **zero tokens**. My "the glider was ~90% verification" was
never a claim about token spend; those tokens went to the experimenter *authoring*
recompute artifacts, and to serial container wall-clock. **Which one dominated has
never been measured.** I built proportionality doctrine on an unmeasured premise
and nearly sequenced a whole phase behind it.

## 5. Bugs I introduced, and the process failure behind them

Three shipped defects, all the same root cause: **asserting an edit landed instead
of observing it, then testing a path that could not reach the change.**

1. A scripted string-replace silently did not match, so `liveview` shipped code
   reading a flag that was never added — `python -m liveview` died on its default
   path. I "verified" with `--once`, which takes the branch *above* the one I had
   written.
2. Change detection compared the **rendered string**, which carries a live clock,
   so it repainted every tick regardless. The user watched the same screen for
   minutes.
3. A module-level `_snap()` in an appended test block shadowed the file's own
   helper and broke 16 unrelated tests.

Guards now in place: a regression test walks every `args.<attr>` the entry point
reads and asserts the parser defines it; change detection reads study state, never
rendered text.

**The meta-lesson, which cost a five-hour usage window:** I let the owner launch a
200M-token run on an ideation restructure that existed only as arithmetic. It
spent 5.6 hours serial and produced nothing.

## 6. What is open

**Blocking:** per-phase cost reporting (item 1) — and it is now *load-bearing*,
not a warm-up, because item 2's premise is unmeasured and `report.json`
**under-counts a study with children by ~3×** (root 18.9M vs true tree 54.0M).
Buildable entirely offline against studies already on disk.

**Then:** a cheap validation run with a hard `--token-budget` — the first live
exercise of the run-killer fixes *and* the ideation restructure.

**Held deliberately:** proportional verification. Building against an unmeasured
belief is the failure mode this project keeps naming. Its candidates are recorded
in `roadmap_status.md` so they are not re-derived — the strongest being that
`free_experimenter.py` still *tells* the agent `publishable` requires every
finding to reproduce, three days after the code was relaxed. A prompt stating a
rule the code no longer enforces: the project's recurring shape, one more time.

**Unbuilt and important:** resumability; a smarter phase system with feedback
edges; cross-study memory that demonstrably helps; a comparison protocol against
a plain chat.

---

## 7. The one-line version

The system went from **weaker than a chat at research** to **doing things a chat
structurally cannot** — decomposing a goal, carrying built work between phases,
catching a failure invisible to any single part, and writing it up honestly —
and the remaining gap is no longer capability but **knowing where its own compute
goes.**
