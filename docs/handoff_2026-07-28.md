## Where the system actually is

The free director works. It decomposes a goal into sub-investigations, carries
built artifacts between phases as re-runnable producers, checks whether the parts
compose, and writes up the study with figures. Two live studies prove it:

- `study-20260726T063702Z` — glider v1. Integration found a fin-moment-arm
  interface defect **invisible to either subsystem alone**. That is the entire
  argument for `call_integration`, demonstrated.
- `study-20260726T185547Z` — glider v2. A design document leading with the
  aircraft, a planform drawing, 127 provenance-tagged values
  (VERIFIED/COMPUTED/JUDGEMENT), independent-route cross-validation, and a
  section that demotes its own headline number because only one of three routes
  reproduced.

Both are also the system's clearest failure: v2 came out ~90% verification, ~10%
design, on a problem the owner could do in five minutes.

## What is NOT true, and must not be assumed

- **Nothing is validated live since 2026-07-27.** The ideation restructure (pool
  76, top-6 deep-reviewed, 2 calls each, 6 concurrent) is arithmetic, not a
  measurement. A cheap run would settle it in ten minutes.
- **A run cannot be resumed.** Two runs have died — one on a usage window five
  hours in — and lost everything. This is the ceiling on the whole vision.
- **Verification is not proportional.** The wall fully re-runs every claimed
  finding; nothing tells the experimenter how much verification the task
  warrants. This is the blocking item.

## The task for this session

**Proportional verification** (roadmap item 4). Everything else gets cheaper once
verification stops eating the budget, and a long complex run is exactly where a
90% ratio becomes unaffordable.

Half of it is done: the REVIEW side is proportional (one good check per claim,
breadth over depth, triage to the best 6). The VERIFICATION side is not.

Shape of the problem, not a prescription:
- A claim the conclusion rests on deserves a check. A supporting number quoted in
  passing may not need one at all, and certainly not three routes.
- The incentive is the root cause: verified findings are the ONLY thing scored,
  so confirming an easy number is the cheapest way to look thorough. A fix that
  only adds instructions will lose to the gradient, as the last one partly did.
- Verification that dominates spend is a failure even when every number
  reproduces.

Build the smallest thing that changes the incentive, then measure it on a real
run before believing it.

## Rules that are not negotiable

- **PRIME DIRECTIVE** (top of `CLAUDE.md`): the system is a FREE agent and must
  never be weaker than a plain chat. Substrates are tools, never a cage. Most
  bugs this month were some prompt forbidding what the agent could already do.
- **Nothing may end an arc except the director.** Screening stages, validators
  and transport failures are recorded as results, never fatal.
- **Verification purity** — no model in the verification path, ever.
- **Never `git add -A`.** Other sessions work in this tree; stage only your files.
- **Run-venue rule** — long runs launch from a plain Terminal under `caffeinate`,
  never a builder-session background task.
- **STOP-and-rule** — changing a contract, a locked schema or a ruled input is a
  decision to record in `docs/`.

## Traps that have bitten repeatedly

1. **Assert-without-looking.** Check every "missing" claim before making it. Much
   of what sounds unbuilt already exists.
2. **Unchecked edits.** A scripted string-replace that silently does not match
   ships code reading a flag that was never added. Assert the replacement, then
   run the actual command.
3. **A smoke test that cannot reach the change.** `--once` passed while the
   default path was dead. Exercise the branch you wrote.
4. **Test fakes have signatures.** Widening an injected callable breaks
   three-arg fakes silently; use the `_seam_accepts_*` introspection idiom.
5. **Shadowing test helpers.** A module-level `_snap()` in an appended test block
   broke 16 unrelated tests.
